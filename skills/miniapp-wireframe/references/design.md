# 视觉与布局规范

## 风格

参考 Hairline 的细线、安静留白和少量立体线稿感，而非把整套 UI 做成 3D 场景。它的交互插画 skill 与本 skill 是不同能力；本 skill 自行生成界面和 SVG，不应宣称运行了 Hairline。

- 审阅画板使用暖灰白 `#f3f3ef`，设备内容为白色。
- 主文字和主要按钮使用近黑 `#242620`；边线用浅灰，建议逻辑尺寸下 1px，复杂 SVG 可用更细笔画。
- 示例的鼠尾草、暖纸色等浅色用于次要强调。新产品已有品牌色时优先沿用，避免强行套用绿色。
- 中文正文采用系统无衬线字体；标题可以加入少量衬线或斜体，保持中文可读性。英文小字仅作辅助，不能承担主要导航。
- 用留白、细边框、排版与轻微底色区分层级；减少重阴影、渐变和装饰卡片。细线不意味着文字低对比或所有文字极小。
- 产品内正文通常 14–16px、辅助文字 11–12px；主要触达区域尽量接近 44px。设备框缩放后的截图大小不等于真实字号。
- 图标使用一致 viewBox、线宽、圆角和光学尺寸的原创 SVG。礼盒等立体插画可用于首页或空状态，交互工具应保持直接清晰。

## 页面组织

先明确用户的主任务，再选择导航。少量主要目的地可采用底部导航；单步工具可省去多余导航。MVP 不默认加入社区、排行榜、创作者市场或复杂会员系统。

编辑类产品可参考以下布局，其他类型按实际任务改造：

- 竖屏：预览在上、工具分组在下，保留稳定主操作；工具区需要滚动时给出可见提示。
- 横屏：预览在左、工具在右，可用侧边导航；保持预览可见，工具区独立滚动。
- 工具按用户意图区分，例如人物、配饰、文字、背景、排版；尺寸、间距和主体大小属于排版，配饰无需藏在人像上传里。
- 滑块名称表达实际含义。排列间距增大应变疏，主体大小独立变化。预览中的长文本要换行或合理裁切，避免重复图案互相覆盖。
- 收费产品先清楚展示价格、适用权益与预览，再进入模拟确认。收费时点及复购规则来自用户需求，不能从案例硬编码继承。

## 横竖屏与审阅

默认只交付一个自适应文件，可用 `matchMedia('(orientation: landscape)')` 或视口宽高判断实际布局。把方向模式（自动、竖屏预览、横屏预览）与业务状态分开。参考案例用 `data-orientation` 控制样式；实际实现也可用 CSS 媒体查询。

建议审阅基准为竖屏 390 × 812、横屏 844 × 390，尺寸可按用户设备改变。设备框、状态栏和微信胶囊为示意，不代表真实安全区或原生控件实现。真实小程序的方向配置、基础库兼容性与系统方向锁定应在实现阶段查阅当前微信官方文档并真机验证，HTML 不替代该验证。

需要自动模式只作用于创作页时，明确页面策略；横屏模式不应迫使所有页面沿用编辑器结构。软键盘出现时，优先保障正在输入的内容和焦点，不因暂时变矮反复重新渲染。
