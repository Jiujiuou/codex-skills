# 滚动叙事汇报页

把汇报内容组织成讲解状态，帮助听众随讲解移动注意力。先确认用户是在要建议、预览还是直接修改；在已有 HTML 上工作时尊重当前结构、内容和授权。

## 选择编排

根据内容选择适合的模式，不必把五种全部用上：

| 内容 | 模式 | 讲解顺序 |
| --- | --- | --- |
| 封面、章节转场 | 滚动触发，定时播放 | 一次手势触发完整过渡 |
| 多项摘要、结论 | 横向逐项切换 | 一次讲一张，底部标识进度 |
| 分层架构 | 总览与逐层聚焦 | 总览 → 每层 → 总览 |
| 前提与推导关系 | 图中镜头聚焦 | 总览 → 相关节点和依据链 → 总览 |
| 网格中的议题 | 单卡展开覆盖整个网格 | 总览 → 展开 → 收回 → 下一项 → 总览 |

一段讲解优先选一种主动画。用于产品首页的装饰动效不是汇报页必需项。用户只要求丰富视觉时，用 SVG、弧线或产品轮廓；不要自行添加事实、数字和文案。

## 实施

1. 阅读目标 HTML，识别现有章节、动画库、滚动监听器、品牌资源和本地依赖。先确定修改位置，避免复制新的监听器造成重复接管。
2. 用数据描述讲解状态，区分「章节」「当前重点」「过渡进行中」。品牌颜色和时间参数集中配置。
3. 有明确讲解节奏时，用手势触发固定时长时间线；只有需要连续探索时才用 `scrub`。这两种方式不可在同一时间线上同时争夺播放进度。
4. 卡片先收回，再让下一张展开；需要全局理解的图表安排开头和结尾总览。停留时画面应稳定，允许演讲者解释。
5. 只给适合的桌面空间开启固定舞台，小屏和减少动态效果时提供可读的静态布局。没有加载动画库时也能访问全部内容。

## 按需读取资源

- 动画实现或复用模块：读 [references/animation-patterns.md](references/animation-patterns.md)。可从 [assets/report-motion.js](assets/report-motion.js) 复制控制器和动画函数；它使用全局 `gsap`，不用构建工具。
- 新建页面或查看完整接线示例：使用 [assets/starter.html](assets/starter.html)，与 `report-motion.js` 放在同一目录。示例文字仅用于演示，按用户材料替换。
- 配色、Logo、箭头及布局：读 [references/design.md](references/design.md)。Wahda 仅是可选预设，不强制用于其他品牌。
- 完成检查、线上发布或定位异常：读 [references/verification.md](references/verification.md)。静态检查不能证明动画在浏览器中可用。

## 必须保留的实现约束

- 固定舞台后 GSAP 会插入容器，定位样式不要依赖可能改变的直接父子关系。
- 缩放和居中要根据实际可见容器、SVG viewBox 和留白计算，同时限制宽、高。监听尺寸改变并重新测量。
- 单次手势只推进一个状态。播放结束后释放输入锁；重新加载、返回顶部、反向、跳转锚点和切换断点都应有明确行为。
- 读取多个节点时使用 `querySelectorAll` 并转为数组。不要把单个元素当数组调用 `.map()`。
- SVG 连线使用节点边界外的端点及明确控制点。一条关系用一条连续曲线；不要先切断折线再逐段平滑，这会产生钩状残段。
- 使用实际官方 Logo 资源并保留比例。不要把近似绘制的标志标成官方原图。
