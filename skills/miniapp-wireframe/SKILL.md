# 小程序 HTML 交互线稿

把产品需求变成可体验、可评审的完整界面原型。线稿是视觉表现，独立 HTML 是交付形式；不要只交付页面说明、静态截图或一幅插画。

## 输入与范围

优先从对话提取产品用途、目标用户、核心功能、主要流程、收费规则和明确排除项。用户无需先定义布局或按钮位置，由你组织页面和信息层级。只询问影响主要流程的缺失信息；其余采用合理假设并简短说明。

沿用用户已确定的范围。参考案例中的包装纸、模板收费和一次购买规则仅为案例，不是新产品的默认业务。没有收费需求时，不添加支付或会员页面。

## 设计与实现

1. 阅读 [视觉与布局规范](references/design.md)，确定适合本产品的导航、主任务和页面结构。
2. 需要复用实现时查看 [单文件参考原型](assets/reference.html)。这是包装纸案例，包含独立 SVG、横竖屏审阅框架和可操作流程；可提取样式或框架，但必须替换业务内容、状态字段、存储键和无关功能。它不依赖 Hairline 的 skill 或软件包。
3. 默认交付 **一个 HTML 文件**，内联 CSS、JavaScript、SVG，使用系统字体；通过 file:// 打开也能运行，不依赖网络、构建工具、外部素材或相邻文件。只有用户明确要求时才拆分文件。
4. 自动根据可用视口切换布局，并提供审阅用的“自动 / 竖屏 / 横屏”控制。方向切换改变布局，不跳转页面，不复制业务状态，不重置输入、照片、当前工具、弹窗或草稿。自动模式优先以视口宽高判断方向；软键盘可能改变视口，应在文本输入期间避免无意义的模式切换。手动方向是预览，不承诺强制旋转设备。
5. 采用单一业务状态驱动两种布局，横屏重新组织分栏和工具位置，不把竖屏界面机械放大或旋转。按本产品实际用途决定哪些页面需要横屏，不把所有小程序都设计成编辑器。
6. 实现能走通的核心路径。主要按钮应产生可见反馈；尚未实现的次要功能明确标注示意。支付、登录、分享等外部流程采用明确的模拟状态，不创建真实订单或发送请求。若使用本地照片，默认仅在浏览器读取。
7. 审阅框架与实际小程序内容分开：说明、方向控制、设计注释放设备框外。用户界面内使用真实产品语言，避免把实现细节和原型免责声明堆进主要操作区。

## 检查与交付

- 用可用的浏览器工具检查至少一遍完整核心流程；覆盖竖屏和横屏，观察滚动、遮挡、弹窗和导航，检查页面错误。
- 在输入内容后切换方向，确认内容和当前步骤保留。窄屏审阅时缩放设备框，真实界面的文字和触达尺寸仍按逻辑像素设计。
- 如包含草稿，检查保存、重新打开以及存储不可用时的反馈。持久化只在产品确有需要时使用，存储键要按项目命名。
- 如包含图片或付费，验证本地图片预览、模拟解锁和重复进入后的正确状态。不要把 PNG/PDF 选项当作已经实现的真实输出；示意下载要注明实际格式。
- 保存最终页面截图。交付 HTML 链接、简短操作说明、主要布局判断和已知模拟边界。没有浏览器工具时说明未完成视觉验证。

本 skill 不要求发布、安装插件或连接后台；这些行动只在用户另外授权的范围内进行。
