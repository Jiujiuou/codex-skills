# 验证与部署

## 有区分的验证

1. 解析内联/外部 JS，核对变量和路径，确认时间线及控制器能初始化。解析通过不能证明运行正常。
2. 资源和 DOM 检查：目标卡片数量、选择器结果类型、节点/边的 ID、Logo 比例、依赖路径。
3. 在可用且允许的浏览器里实际操作：一手势一状态、连续滚轮、触摸与键盘、反向回看、锚点跳转、最后一页出口。
4. 检查窗口变化和 reduced-motion；无 GSAP 时所有内容可读。不要把“语法通过”写成“动画已验证”。

没有浏览器验证能力时保留成果，准确说明尚未验证的部分；不得绕过工具明确禁止的访问路径。

## 推荐画面

至少观察一种常规桌面（如 1440×900）、一种宽屏（如 2560×1080）和一种窄屏。重点查看完整内容而非固定截图尺寸：标题不挡图、卡片展开不越界、箭头不被方框遮住、左侧与较长右侧居中。

## 常见故障与定位

| 现象 | 优先检查 |
| --- | --- |
| 样式变化但无动画 | 控制台错误，特别是单节点 `.map()`、未定义状态 |
| 固定后布局变化 | pin-spacer 使直接子级选择器失效；嵌套 transform 改变 fixed 的包含块 |
| 放大裁切 | 实际容器尺寸、两轴缩放、padding 和 SVG 留白 |
| 放大突然跳变 | snap 与独立播放争抢、过短的滚动区间、文字重排 |
| 一次跳过几页 | 监听器重复、惯性尾部、输入锁过早释放 |
| 返回后空白 | 状态未重置、结束态隐藏未还原、断点清理不完整 |

## 单文件交付与 GitHub Pages

示例默认用相对路径加载 `report-motion.js`，演示依赖 CDN 上的 GSAP。交付单 HTML 时将 motion 文件内容内联；Logo 可使用 data URI，其他资源需一并打包。离线演示需要下载所用库并核对资源路径。

GitHub Pages 默认入口是 `index.html`；项目站点通常为 `https://USER.github.io/REPO/`，包含仓库名。选择 main 根目录发布时，入口位于该分支根目录。遇到 404 先确认实际网址、上传位置与 Actions 部署结果。

只有用户要求部署时才执行远端发布。部署方式随 GitHub 产品变化，以当时官方说明核对：https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site。
